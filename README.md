# CMAI Tracker

A progressive web app (PWA) for caregivers. Log each agitated behavior as it happens, and see Cohen-Mansfield Agitation Inventory (CMAI) scores for every 14-day period. Works offline and installs to a phone's Home Screen.

Built by Devin Ferrell for the Hands-On Lab, Old Dominion University (hands-on interview, October 2026).

## What the lab asked for

> "We need to develop a CMAI form app that allows caregivers to record each time they observe a behavior listed in the CMAI, such as kicking or hitting. The app should save each observation and calculate the CMAI scores every 14 days. It should display the total score and individual scores for each behavior to help us track agitation patterns over time."

## The one design decision that matters

The CMAI isn't a count. It's a caregiver's look-back rating (1 to 7) of how often each behavior happened over the last two weeks (manual p.5). This app counts events, so it converts each 14-day count into a 1 to 7 rating with a written, tested rule. The caregiver then confirms or corrects those ratings at day 14. The full rule and the decisions the lab still needs to make are in [docs/scoring-spec.md](docs/scoring-spec.md).

## What it does

- **Log:** 29 buttons, one per CMAI behavior, grouped the way the manual groups them. Each button shows the manual's definition, plus a "Does not count" note where the manual excludes things. You can undo a tap, mark the time as approximate, or note what happened just before.
- **Scores:** per-behavior ratings for each period, agitated or not for three behavior groups (manual thresholds), group averages over time, the total (labeled secondary), and when in the day behaviors happen.
- **Day-14 review:** confirm or change each rating, including codes 8 (prevented) and 9 (not applicable).
- **Patients & data:** pseudonymous patient codes only, six weeks of demo data, export to JSON and CSV.

## Run it

```bash
npm install
npm test          # 22 tests, including 17 hand-scored cases from docs/test-cases.json
npm run dev       # http://localhost:5173
npm run build     # production build in dist/, with service worker
npm run preview   # serve the build at http://localhost:4173
```

Deploy: every push to `main` runs the tests, builds, and publishes to GitHub Pages (`.github/workflows/pages.yml`). Pull requests run the tests and build only.

## How the code is organized

| Folder | What's in it |
|---|---|
| `src/scoring/` | The CMAI items and the scoring engine. Pure functions, no screens or storage, so they can be tested and reused on other platforms. |
| `src/data/` | Local storage (IndexedDB through Dexie), demo data, export. |
| `src/ui/` | The four screens. |
| `docs/` | Scoring spec, hand-scorable test cases, research notes. |
| `tests/` | Runs the engine against every case in `docs/test-cases.json`. |

## For the other platform builds

`docs/scoring-spec.md` and `docs/test-cases.json` don't depend on any platform. If the iOS and Android versions pass the same cases, all three apps give the same scores for the same logs.

## Privacy

Data stays on the device until someone presses Export. Patients are codes, never names. This is a prototype. Before it touches real patient data, it needs the lab's approval process (IRB) and permission to reproduce the CMAI text, which is copyrighted ("Cohen-Mansfield, 1986. All rights reserved").

## How this was built

Most of the code was written by an AI coding agent (Claude) working from my written requirements. I wrote the requirements and the scoring spec, designed the test cases, reviewed the code, and made the release decisions. The test cases' expected answers were written by hand from the spec, not generated by the engine, so the tests check the engine against the spec.
